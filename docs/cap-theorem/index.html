CAP 定理

把一份数据复制到三台机器,你就免费买到了可用性,也签下了一份风险合同:网络一旦把集群劈成两半(P=分区容忍,必选——网络必然故障),复制之间就出现裂口,这时 C(线性一致)与 A(处处可响应)只能保一个——Gilbert 与 Lynch 2002 年证明了这条 CAP 定理;CP 阵营(ZooKeeper、etcd):分区时少数派宁可不服务,等多数派凑齐再写,一致性无价;AP 阵营(Cassandra、DNS):两半都继续收写,各留一份「暂时的真相」,愈合后再用向量时钟/最后写入胜出等策略合并——期间读到的可能是旧数据;被误读最多的是「三选二」:没有分区时 C 与 A 可兼得,真正的日常权衡是延迟(PACELC),Quorum 滑杆(W+R>N):读多写少调 W、写多读少调 R;理解 CAP 的正确姿势不是背结论,而是盯着「分区发生的那一秒」——所有分布式数据库的架构分歧,都是从那一秒开始分岔的。拖「写 Quorum W」看写入要凑几张票,拖「读 Quorum R」看读到多新的数据;按「无分区基线」看复制流水线,按「分区-CP」看少数派拒绝写入,按「分区-AP」看两半真相分叉,按「愈合与冲突」看版本合并收场。3D 交互演示 · 鼠标拖动旋转 / 滚轮缩放 · 空格播放/暂停
