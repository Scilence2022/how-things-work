CRC 循环冗余校验

网线上、压缩包里、SSD 闪存间,每天有万亿量级的 CRC 在值班,而它的全部数学只有一句话:把比特串看成 GF(2) 上的多项式——系数只有 0 和 1、加法是不进位的 XOR——然后除以双方约定的生成多项式,把余数附在消息后面;接收方整除一遍,余数非零就是传输出错。不进位的世界里除法只剩下移位和 XOR,硬件实现是一排移位寄存器加几个异或门(LFSR):数据流过时除法同步进行,一位延迟一个门,千兆网线上一秒钟做十亿次。它的检错能力精确可控:生成多项式只要含两个以上非零项,所有单个比特错必被抓;阶数为 r 的 CRC,长度 ≤ r 的突发错误全部可检——CRC-32 的 32 位余数让 5 字节以内的任何突发无处遁形,还对长度小于 2³¹ 的消息保证双重错可检。但要分清:CRC 不是密码学哈希,它能防错误不防恶意——攻击者可以计算并补出一个让 CRC 通过的恶意消息,所以 TLS 之外还要 HMAC;以太网帧尾 4 字节 FCS、ZIP 的 CRC-32、蓝牙与 USB 的 CRC-16/32,全是这条 1961 年数学的现役部署。拖「生成多项式」换 CRC-8/16/32 看检错范围,拖「注入错误」翻转比特;按「长除慢放」看移位-XOR 一步一顿,按「单位错演示」看余数报警,按「突发错误」连翻五个比特。3D 交互演示 · 鼠标拖动旋转 / 滚轮缩放 · 空格播放/暂停
