缓冲区溢出与内存安全:越界的字节

C 语言不检查数组边界:把 100 字节写进 64 字节的栈缓冲区,多出来的 36 字节会顺着栈向上「淹没」相邻数据。栈帧从低地址到高地址依次摆着:局部变量(含缓冲区)→ 保存的帧指针 → 返回地址;输入足够长时,返回地址就被攻击数据覆写——函数执行 ret 时,程序计数器被装上这个伪造值,控制流跳到攻击者指定的位置,这就是 1988 年莫里斯蠕虫利用的经典漏洞,数千台机器一夜沦陷。三十年防御进化:金丝雀 canary 在函数入口于返回地址前放一个哨兵值,返回前检查,被改即终止进程;ASLR 地址空间随机化让每次启动的栈/堆/共享库基址随机,写死的偏移失效;NX/DEP 把栈页标记为不可执行,注入的代码根本跑不起来;攻击者于是改用 ROP 面向返回编程,拼接程序里现成的代码片段(gadget)绕过 NX,防线又催生 CFI 控制流完整性;釜底抽薪是 Rust/Go/Java 这类内存安全语言的运行时边界检查——微软与谷歌统计自家产品约 70% 的严重漏洞源于内存安全问题,行业正在用 Rust 重写关键组件。工程教训:永远检查长度、用带边界的 API、开满编译器保护(-fstack-protector 等)。演示:拖「输入长度」滑块把数据块逐格灌进栈塔,亲眼看它越过 buf 边界、染红金丝雀与返回地址;按「函数返回」看四种结局——无防御时控制流被劫持、金丝雀报警当场终止、ASLR 让写死的跳转地址失效、NX 页拒绝执行;开「边界检查写入」对照安全版本,再按「重新调用」在 ASLR 下换一组随机基址。3D 交互演示 · 鼠标拖动旋转 / 滚轮缩放 · 空格播放/暂停
