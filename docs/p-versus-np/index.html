P 与 NP:验证容易,求解未必

排序、最短路这类问题,计算机能在多项式时间内直接「求解」,归入 P 类;而填好的数独逐行、逐列、逐宫一扫便知没有重复,大合取式拿一组赋值逐项核对便知真假——这类「验证答案很容易」的问题归入 NP 类。显然 P⊆NP,真正的难题是反方向:验证容易,是否意味着求解也容易?这就是克雷研究所悬赏百万美元的 P vs NP。沟通两边的桥梁是归约:把问题 A 的实例多项式地翻译成问题 B 的实例,解出 B 就等于解出 A;Cook-Levin 定理证明布尔可满足性 SAT 是 NP 完全的(NP 中最难的代表),Karp 随后把 3SAT、团、顶点覆盖、哈密顿回路、图着色、背包、TSP 判定版等 21 个经典问题逐一归约连通——全体 NP 完全问题一荣俱荣、一损俱损:任何一个找到多项式算法,全体沦陷。密码学押注 P≠NP(更精确地说依赖单向函数):RSA 们的安全性正建立在「验证容易、求解很难」的不对称上。实用主义三招:近似算法(TSP 的 Christofides 有 1.5 倍保证)、参数化算法(按小参数 k 指数、按 n 多项式)、工业 SAT 求解器(最坏指数、常数极小,实解上万变量)。彩蛋:随机 3SAT 在「子句数/变量数」比值 α≈4.267 处可满足率从 1 骤降到 0——约束密度的相变,最难的实例恰好聚集在阈值附近。演示:数独棋盘看验证扫查瞬间完成、回溯搜索树节点暴涨;拖 n 滑块看 2ⁿ 穷举柱与 n² 验证柱的剪刀差;跑归约动画看 3SAT 变成团;调 α 按「采样 3SAT」亲手撞上相变。3D 交互演示 · 鼠标拖动旋转 / 滚轮缩放 · 空格播放/暂停
